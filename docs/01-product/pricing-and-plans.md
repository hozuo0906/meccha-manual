# 料金プランと利用上限

Status: Accepted

## 商用MVPでの位置づけ

本書にある課金契約は、Stripe実装時の安全な技術契約として保持する。ただし、初回商用MVPのActivation条件にはしない。

- `BILLING_FEATURE_ENABLED=false` を維持したまま、まず `操作を記録 -> 下書き生成 -> 編集 -> URL共有` の価値検証を行う。
- 初回ユーザーが価値を体験する前に、料金プラン選択やCheckoutを主要導線へ置かない。
- 課金公開前に、Activation Rate、Second Manual Rate、D7 Creator Retention、Invite Rateを確認する。
- 初期の商品設計は `Free -> Pro -> Team` の段階を第一候補とし、利用者に見せる制限軸を最小化する。
- Browser Run時間、R2容量、同時記録数は原価・安全制御としてサーバー側で保持してよいが、通常利用者へ常時すべて表示しない。
- `single_export` の都度払いは技術契約を削除しないが、初回商用MVPではDeferredとする。実装・公開は単発利用の需要が確認された後に再判断する。
- 下記の 550円 / 3,300円 / 9,900円 は現行Accepted契約として保持するが、課金公開前に価格テストの仮説として再評価できる。変更時は既存の変更管理手順に従い、関連ADR等を同時更新する。

## 商品設計の原則

利用者向けの料金説明では、技術原価ではなく利用価値を中心にする。

- Free: 最初の手順書を完成・共有し、継続価値を確認できることを優先する。
- Pro: 継続的に複数の手順書を作成・運用する個人向け。
- Team: メンバー招待、共同管理、権限などチーム利用の必要性が発生した利用者向け。

Freeの正式な本数・時間・保存上限は、Browser Run/R2の実測原価と初期利用データを見て決める。Activationを阻害するほど低い制限を、原価実測なしで先に固定しない。

## 目的

`めっちゃマニュアル` の料金、課金単位、利用上限、エクスポート権を固定し、画面、Stripe、entitlement、利用量計測が同じ契約を参照できるようにする。

初期状態では `BILLING_FEATURE_ENABLED=false` を維持し、本書の価格を決めたことだけを理由にStripe商品作成、Webhook endpoint作成、Secret登録、課金機能有効化を行わない。

## 提供形態

ユーザー向けには「ショット」ではなく「都度払い（1マニュアル買い切り）」と表示する。内部識別子は英語のoffer codeを使う。

以下は課金機能を有効化する場合の現行技術契約である。商用MVPの初回提供順序は上記「商用MVPでの位置づけ」を優先する。

| 提供形態 | offer code | 税込価格 | 対象 | エクスポート | Browser Run | R2保存容量上限 | 同時記録 |
|---|---|---:|---|---|---:|---:|---:|
| 都度払い | `single_export` | 550円 / 1マニュアル | 単発利用 | 購入対象の1マニュアルを購入日から30日間、PDF/HTML/Markdownで再出力可 | 未契約作成枠を利用 | 未契約作成枠を利用 | 1 |
| パーソナル | `personal_monthly` | 3,300円 / 月 | 1人の継続利用 | 契約中は無制限 | 月5時間 | 5GB | 1 |
| チーム | `team_monthly` | 9,900円 / 月 | 複数人の共同利用 | 契約中は無制限 | 月20時間 | 25GB | 2 |

すべて税込みとする。年額プラン、従量超過課金、追加席、追加容量は初期提供に含めない。

## 未契約作成枠

都度払いの購入前にも手順書を作成できるよう、認証済みワークスペースへ次の安全枠を設ける。

- 操作記録は月60分まで。
- 下書きは同時に2件まで。
- 同時記録は1セッションまで。
- 未契約作成枠のR2保存容量上限はOQ-026で決める。上限確定前に課金公開や無制限保存を有効化しない。
- エクスポートは、対象マニュアルの都度払い完了または有効なサブスクリプションが確認できるまで実行しない。
- 上限超過による自動課金は行わず、新しい操作記録または保存を停止して料金案内を表示する。
- 未決済下書き、操作記録画像、購入後データの保持期間はOQ-023で決める。

上記は課金契約上の安全枠であり、商用MVPのFree体験としてそのまま採用するとは限らない。Free公開前に、Activationへの影響と実測原価を確認し、必要ならADR等を同期して見直す。

## メンバーと席数

- パーソナルもワークスペースを必須とするが、有効メンバーは1人に限定し、メンバー招待を提供しない。
- チームは有効なowner/admin/editorを作成者として数え、5人まで含める。ownerも1作成者として数える。
- チームはviewerを50人まで含める。viewerは作成者席へ数えない。
- 招待中、停止中、猶予期間中のメンバーを席数へ含める条件はOQ-015で確定する。
- 席数超過時に既存ownerを自動で締め出さず、新規招待と新しい権限昇格を停止する。
- TeamからPersonalへの契約置換と既存メンバー処理はOQ-027が決まるまで自動化しない。active/grace/read_onlyのTeam契約があれば人数に関係なくPersonalのCheckout Sessionを作成せず、課金前に移行を停止する。

## エクスポート権

### 都度払い

- 購入権は `workspace_id` と `manual_id` に固定し、別マニュアルへ移せない。
- 1回の購入でPDF、HTML、Markdownの各形式を利用できる。
- 購入日から30日間は、同じマニュアルを修正して再出力できる。
- 30日経過後もアプリ内の手順書データを自動削除しない。再出力には新しい都度払いまたは有効なサブスクリプションが必要になる。
- 公開済みファイルやユーザーが保存したファイルを、返金後に遠隔削除できるものとして扱わない。

### サブスクリプション

- パーソナルとチームは契約有効期間中、ワークスペース内の手順書を回数制限なしでエクスポートできる。
- 解約予約中は支払済み期間の終了まで利用できる。
- 未払い時は即時削除せず猶予状態へ移し、猶予期間終了後の読み取り専用化はOQ-016で決める。

## 利用量の扱い

- Browser Runはセッションの課金対象実行秒数を月次で集計する。
- 保存容量は削除済み扱いでURL発行を止めたobjectを含め、物理削除完了まで実使用量として監視する。
- 80%到達時に警告し、100%到達時は新しい操作記録、新規保存、新しいエクスポート生成を停止する。
- 既存手順書の閲覧と、すでに生成済みで期限内のエクスポート成果物のダウンロードは継続する。新規生成は一時objectを含め容量を消費するため、削除で空きを作った後に再実行する。
- 利用量集計の不整合時に追加請求せず、管理者へ再集計状態を表示する。

利用量は初期から正確に内部計測するが、一般利用者へ複数のメーターを常時見せる必要はない。警告・停止・プラン判断に必要な情報だけを段階的に表示する。

## Stripe Checkout SessionsとLink

- 申込入口は購入試行ごとにサーバーが作成する短命なStripe Checkout Sessionとし、固定のPayment Link URLをentitlement付与に使わない。
- Stripe LinkをCheckoutの高速決済手段として有効化し、利用者が保存済みの支払い情報を呼び出せるようにする。
- Linkのメールアドレスやログイン状態を、`めっちゃマニュアル` の認証、ワークスペース所属、権限付与の根拠にしない。
- アプリで推測不能なcheckout intentを発行し、そのIDだけをCheckout Sessionの `client_reference_id` として渡す。
- アプリの購入操作とStripeのSession作成の両方へintent由来のidempotency keyを使い、並行送信や応答消失時は同じintent/Sessionを返す。
- Checkout Sessionはcheckout intentと1対1に固定し、30分で失効させる。期限切れSessionはStripe側でも支払い不能にする。
- Webhookではcheckout intent、Stripe上のPrice、支払状態、対象ワークスペースとマニュアルを照合する。
- 決済完了画面へのリダイレクトだけでentitlementを付与しない。

## 課金開始のProduct Gate

Stripeを有効化する前に、少なくとも次を確認する。

- 初回Activationが実ユーザーで再現できる。
- 2本目を作成する利用者が存在する。
- Free上限のどの制約が原価または商品価値上必要か説明できる。
- Proで購入される価値が、単なる技術制限解除ではなく明確になっている。
- Teamは実際に招待意図が確認されてから主要導線へ出す。

これらはセキュリティの課金ゲートを置き換えず、Product Gateとして追加する。

## 変更管理

価格、税込み設定、利用上限、再出力期間、席数を変える場合はADR、decision-log、課金ハーネス、環境変数台帳、受入条件を同じPRで更新する。Stripe側の外部設定変更は文書変更とは別に明示承認を必要とする。
