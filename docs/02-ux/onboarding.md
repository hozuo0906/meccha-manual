# オンボーディング

Status: Accepted

## 目的

初回利用者が管理概念を学ぶ前に、実際の手順書を1本完成し、共有できる状態まで到達することをオンボーディングの目的とする。

オンボーディング完了は「ログインできた」「workspaceを作った」ではなく、`操作を記録 -> 下書き生成 -> 編集 -> 共有` の完遂で判定する。

## 初回導線

1. LPまたは招待導線から開始する。
2. メールOTP等で認証する。
3. 個人利用者には内部workspaceを自動準備する。
4. 初回画面で `最初の手順書を作る` を主要CTAとして表示する。
5. 必要であれば短い用途選択を行う。
   - 経費精算
   - 勤怠・申請
   - CRM / 顧客管理
   - その他
6. 記録開始前に、入力値を保存しないことと、記録できないサイトがあることを短く案内する。
7. 操作を記録する。
8. 記録終了後、自動生成された下書きを表示する。
9. タイトル、説明、不要ステップ、マスキングだけを優先して修正できるようにする。
10. `共有する` を主要CTAとして表示する。
11. 共有後に成功状態を表示し、次の行動として `2本目を作る` と `メンバーを招待` を案内する。

## 初回に要求しないこと

次は価値体験より前に利用者へ設定させない。

- workspace名の決定。
- owner/admin/editor/viewerの理解。
- メンバー管理。
- 保存容量の選択。
- Browser Run時間の選択。
- revisionや公開版の内部構造理解。
- 料金プランの比較。
- Stripe決済。

安全上必要な同意や制約説明は例外とするが、長い説明文を読まないと開始できない構造にはしない。

## 初回画面

### 空状態

初回ログイン後に空の表だけを見せない。

表示優先度:

1. `最初の手順書を作る`
2. 「操作を一度記録すると、画像付きの手順書になります」の一文
3. 安全性についての短い補足
4. 必要な場合のみサンプルを見る導線

### 記録開始前

最低限伝えること:

- 入力した文字列そのものは保存しない。
- パスワードやカード番号等は保存しない。
- サイトのセキュリティ設定により記録できない場合がある。

利用者にSSRF、egress、Browser Runなどの技術用語を表示しない。

### 記録失敗

エラーは次の順で表示する。

1. 何が起きたか。
2. どこまで保存されたか。
3. 次に何を試せるか。

対象サイトの制約で継続できない場合は、無限再試行させず、手動で手順を作る・別の画面で試す等の安全な代替導線を提示する。

### 下書き生成後

最初から全編集機能を展開しない。

優先操作:

- タイトルを直す。
- 不要なステップを消す。
- 説明文を直す。
- 必要箇所をマスキングする。
- 並べ替える。

高度な設定は折りたたむか、通常導線外へ置く。

### 完成・共有

共有完了時は成功を明確に伝える。

主要行動:

1. 共有リンクをコピー。
2. 2本目の手順書を作る。
3. 必要な場合だけメンバー招待。

課金案内は、無料枠の価値を体験する前に主要CTAとして出さない。

## Activation定義

Activationは次の条件をすべて満たした時点とする。

- 初回manualが作成されている。
- 1件以上のstepが存在する。
- 利用者が生成結果を確認している。
- manualが共有可能な状態になっている。

共有URLを実際に他者が閲覧した場合は `Activated + Shared` として別に計測する。

## 計測イベント

最低限次を記録する。

| event | 意味 |
|---|---|
| `onboarding_started` | 初回導線開始 |
| `capture_started` | 記録開始 |
| `capture_failed` | 記録失敗 |
| `capture_completed` | 記録終了 |
| `draft_generated` | 下書き生成 |
| `first_manual_completed` | 最初の手順書完成 |
| `share_enabled` | 共有有効化 |
| `shared_manual_viewed` | 共有先で閲覧 |
| `second_manual_created` | 2本目作成 |
| `member_invite_started` | チーム拡張意図 |
| `upgrade_started` | 課金意図 |
| `upgrade_completed` | 課金完了 |

イベントpayloadへ入力値、Cookie、Authorization、スクリーンショット本文、機密queryを含めない。

## UX KPI

- Activation Rate。
- TTFV。
- Capture Completion Rate。
- Share Rate。
- Second Manual Rate。
- D7 Creator Retention。

初期改善では、設定画面の機能充実よりこれらの指標改善を優先する。

## Teamへの拡張

個人が価値を得た後にだけTeam機能を段階的に開示する。

`共有 -> 繰り返し利用 -> メンバーを招待したい -> Team機能を案内`

メンバー招待開始までは、4ロールや席数を初回体験の中心に置かない。

## セキュリティ境界

オンボーディング簡素化を理由に次を弱めない。

- Access主体検証。
- workspace/tenant分離。
- private storage。
- 入力値非保存。
- 共有リンク失効。
- SSRF/egress fail closed。
- ログへのsecret非出力。
