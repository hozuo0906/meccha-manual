# UX原則

Status: Accepted

## 基本方針

`めっちゃマニュアル` はWikiではありません。操作を記録し、業務手順として確認、保存、共有、更新するための作業台です。

最初のUX目標は、利用者にアカウントや管理機能を理解させることではなく、最短で `Chrome拡張導入 -> 表示モード選択 -> 操作記録 -> ローカル下書き確認 -> 必要最小限編集` まで到達してもらうことです。

## Time to First Value

- 初回価値体験より前にアカウント作成を要求しない。
- workspace、role、storage、usage、revision等の内部概念を必要になるまで見せない。
- LPの主要CTAは `無料で手順書を作ってみる` 等、成果物作成を直接示す。
- Chrome拡張未導入なら拡張導入、導入済みなら表示モード選択／記録開始へ一直線にする。
- guestでlocal draft完成まで進める。
- `保存 / 共有 / PDF出力` を押した時点で初めてアカウント作成／ログインを要求する。
- signup後は同じguest draftと選択済みoutputへ自動復帰し、やり直しを要求しない。

## Progressive Disclosure

- guest中はworkspace自体を作成しない。
- signup後のPersonal Workspaceはserver側で自動準備し、初回タスクにしない。
- `メンバーを招待` を選ぶまで4ロールや席数を前面に出さない。
- 課金上限や保存容量は意思決定に必要なタイミングだけ案内する。
- 下書き／revision等の内部状態は利用者語彙に変換し、通常画面では `編集中` / `公開中` 等を基本とする。
- 高度な設定は基本導線の外に置く。

## 画面原則

- 初回空状態では管理一覧より作成導線を優先する。
- 手順書閲覧は縦スクロールを基本にする。
- エディタは手順一覧と内容を中心にし、詳細編集は必要な時だけpanel/dialog等で開く。
- 常時3ペイン固定を必須にしない。
- guest editorと認証後editorで基本操作・用語を変えすぎない。
- 設定はフォームで扱う。
- 何でもカードにしない。
- 公開閲覧画面に管理画面用ナビゲーションを出さない。
- 主要CTAを同じ視覚階層で複数並べない。

## PC・スマホ・タブレット

手順書作成前に表示モードを簡単に選択できるようにする。

- `PC`
- `スマホ`
- `タブレット`

スマホ／タブレットでは必要に応じて `縦向き / 横向き` を選ぶ。

利用者向けにはresponsive viewport等の技術用語を出さず、「スマホ表示」「タブレット表示」と表現する。ただし実機iOS/Android完全再現ではないことを誤解させない。

記録終了、取消、失敗時は元のChrome window状態へ戻す。

## 初回オンボーディング原則

- 製品説明より先に成功体験を作る。
- サンプルだけで完了扱いにせず、利用者自身の業務画面で1本作る導線を主とする。
- Chrome拡張permission warningと実際の権限が一致することを確認する。
- 記録開始前に「対象タブだけ」「入力内容・Cookie等は保存しない」を短く案内する。
- 記録失敗時は技術用語ではなく、どこまで残っているかと次の操作を案内する。
- local draft完成後は保存・共有・PDF等の成果物CTAを示す。
- output gateのsignup画面では「登録するといま作った手順書を保存できます」のように、登録理由を直前の目的へ結びつける。
- signupをキャンセルした場合はlocal draftへ戻す。

## Output Gate

アカウント作成を要求する代表操作:

- 保存。
- 共有。
- PDF出力。
- Teamへの引き継ぎ。

output gateでは利用者が押した目的を保持する。認証後に別のダッシュボードへ飛ばして操作文脈を失わせず、`bootstrap -> guest claim -> 元output` を自動継続する。

## 文言

- 丁寧だが短い `です・ます` 調。
- 英語やカタカナの多用を避ける。
- ボタンは行動を明示する。
- エラーは `何が起きたか -> どこまで残ったか -> 次に何をするか` の順に書く。
- `workspace`、`revision`、`entitlement`、`claim intent` 等の内部語彙を一般利用者向け画面へ直接出さない。
- `スマホ表示`を実機完全再現と誤認させる表現をしない。

## 状態

必要な状態を区別するが、利用者の次行動が変わらない内部状態は統合表示する。

代表状態:

- 記録準備中。
- 記録中。
- ローカル保存済み。
- signup待ち。
- 引き継ぎ中。
- 保存中。
- 保存済み。
- 保存失敗。
- 共有中／共有済み。
- 接続切断。
- 権限不足。

## Product UX計測

イベント名・payloadは `docs/05-api/product-events.md` を正本とする。

UX改善では少なくとも次を見る。

- LP -> extension install。
- extension install -> capture start。
- capture start -> local draft。
- local draft -> output gate。
- output gate -> signup complete。
- signup -> guest claim。
- first manual -> share。
- first manual -> 7日以内のsecond manual。

計測のために入力値、URL本文、screenshot本文、Cookie、Authorizationを保存しない。

## アクセシビリティ

- 色だけで状態を伝えない。
- ドラッグ操作にはボタン操作の代替を用意する。
- アイコンボタンにはツールチップとアクセシブル名を付ける。
- 本文16px以上、一覧14px以上、タッチ対象44px以上を目安にする。
- 初回導線、output gate、エラーからの復帰でもキーボード操作とフォーカス移動を省略しない。
