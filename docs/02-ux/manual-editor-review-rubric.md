# 手順書作成体験の受入レビュー

Status: Proposed

Date: 2026-10-01

## 対象と判定

記録開始、記録中、下書き・保存済み手順書一覧、編集、ブランド設定、保存・認証復帰、共有確認、共有閲覧を一つの体験として評価する。初期案の見た目だけでは採点しない。

独立した複数の評価者が、同一候補の実画面と操作証跡を確認し、互いの点数を見る前に100点満点で採点する。合格には各評価者が80点以上であることが必要。平均80点は合格条件ではない。未実行の項目は未確認とし、静的ソースレビューを実画面レビューの代わりにしない。

| 観点 | 配点 | 確認すること |
|---|---:|---|
| 目的と次の操作の分かりやすさ | 15 | 初回はゲストから開始でき、記録対象・終了・編集への導線を説明なしで理解できる |
| 情報の優先順位と画面の統一 | 20 | 画像が主役、保存前後で同じ操作構造、一覧・設定・共有・閲覧で色・余白・書体が一貫 |
| 編集の速さと位置の保持 | 20 | 20手順の17番を編集、追加・並べ替え・削除・取り消し、画像道具が文脈に合いフォーカスが残る |
| 状態・失敗・中断からの復帰 | 20 | 画像処理、取得失敗、表示失敗、保存先と保存結果、認証中断、共有結果不明を区別して回復できる |
| 読みやすさとアクセシビリティ | 15 | 日本語の自然さ、キーボード、コントラスト、44px操作目標、色以外の状態、動きを減らす設定 |
| 狭い画面とブランドの出力品質 | 10 | 1366/1024/390pxで切れない、200%拡大、ロゴ比率・余白とテーマ色が共有閲覧・出力でも崩れない |

## 点数と別の必須安全条件

個人情報・秘密値の漏出、誤った手順への画像の関連付け、手順や未完画像の黙った欠落、未保存なのに保存成功と表示、共有する版の取り違え、テナント境界越えが一つでもあれば不合格。点数で相殺しない。

## 再現する操作

1. 合成業務画面で記録開始、連続クリック、入力後クリック、タブ変更、終了して編集
2. 20手順の17番で説明・矩形色・画像を編集、16番へ移動、追加・削除・取り消し・やり直し
3. 画像デコード・端末保存が遅延中に保存と共有を押す。失敗させて同じ手順から回復
4. ログインを閉じる、戻る・再開、同じ下書きと選択位置へ復帰
5. クラウド保存中にも入力し、最新の入力とフォーカスが保持される。再読込失敗を成功表示しない
6. 共有確認を開閉、期限・パスコードを確認し、通信中断後は同一操作として照会・再試行
7. ロゴと色を設定し、明暗のテーマ・縦長/横長ロゴでヘッダー、共有版、印刷を確認
8. 共有閲覧で17/20へ進み、別タブ復帰・再読込・画像失敗・期限切れを確認

評価には候補commit、画面幅、操作、スクリーンショット、各観点の点数と減点理由、未確認範囲を添える。修正後は影響箇所を再試験し、最後の候補で全体を再評価する。
