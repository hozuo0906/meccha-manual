# ADR-0017 サブエージェント品質loop

Status: Accepted

## 背景

めっちゃマニュアルは、親セッションを頭にして、コーディング、UIUX、テスト、辛口レビュー、リファクタリング/コードレビュー、ドキュメント記録の観点を確認する。各観点の結論がPRに残らないと、AI駆動開発の速度は出ても品質判断が曖昧になる。DEC-066により、これは6個の専任サブエージェントや別taskを必須にする契約ではなく、親PMと限定範囲の作業担当による独立タスクで実証確認する契約へ更新する。

## 決定

- PRごとにサブエージェント品質loopを通す。名称とファイルは既存CI／PRテンプレート互換のため維持する。
- PRテンプレートに各観点の確認項目を入れる。専任6担当の起動は要求せず、対象範囲に応じて作業担当が確認し、親PMが実証照合する。
- 現行の独立タスク体制では、親PMを`gpt-6-astra`（high）、作業担当を`gpt-5.6-luna`（high）とし、作業担当はサブエージェントを使わず、次taskを自己増殖させない。
- 起動形態の正本はDEC-066と`docs/09-delivery/decision-log.md`／`session-handoff.md`とし、本ADRと品質loop手順は品質ゲートを定義する正本として、それを弱める解釈をしない。
- `Quality Loop Gate` workflowで、品質loopのdocs、ADR、報告テンプレート、PRテンプレートが存在することを検証する。
- サブエージェントの生思考や会話全文は記録しない。結論、根拠、採否、リスク、未決だけを要約する。
- P0/P1が残る場合はmergeせず、修正loopへ戻す。
- Codex Reviewは最新head SHAを対象にし、指摘後は修正・テスト・再レビューを必須とする。未解決thread、古いSHAのレビュー、API確認失敗がある場合はfail closedでmergeを止める。

## 理由

- 作業速度を落とさず、レビュー漏れ、テスト漏れ、定数や責務の散らばりを早期に止めるため。
- 各観点の役割をPR上で見える化し、ユーザーがDiscordやGitHubで判断しやすくするため。確認主体を専任サブエージェントに固定せず、親PMが実証照合できる形にするため。
- Phase 1以降の本番開発で、機能ごとの品質ゲートを同じ型で回すため。

## 影響

- PR作成時に品質loopチェックリストが表示される。
- `npm run check` は `quality-loop:check` を含む。
- 品質loopの正本は `docs/09-delivery/subagent-quality-loop.md` と `docs/09-delivery/subagent-report-template.md` とする。
- 上記2ファイルとPRテンプレートの「サブエージェント」名称は既存CI／PR互換名であり、現行体制で専任6タスクを必須とする意味ではない。
