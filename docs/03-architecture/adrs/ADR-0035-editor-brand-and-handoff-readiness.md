# ADR-0035: 拡張編集画面のブランド統合と認証後handoff準備表示

Status: Accepted

Date: 2026-09-27

## Context

Chrome拡張の編集画面は、画像を中心に手順を整え、明示した保存・共有操作へ進む現行MVPの主要な出力境界である。従来の仮スタイルでは、保存状態、機密マスク、handoff準備中の状態が伝わりにくく、共有URLを開いた直後に外部認証の画面だけが見える場合があった。

## Decision

- 編集画面は墨色の本文に淡い水色・淡い緑の面を組み合わせ、採用済みのロゴと「め」キャラクターをヘッダー、保存・共有ダイアログ、handoff準備表示へ使う。英語の装飾見出しはUIへ出さず、日本語を基本とする。
- 手順一覧はカード状の選択面、本文は画像中心の編集面とし、画像上のドラッグで機密マスクを追加できること、保存・共有時にもマスクが引き継がれることを説明する。元画像や認証情報をhandoff metadataへ複製しない契約はADR-0032を維持する。
- 保存状態は「編集中」「保存中…」「保存済み」「保存できません」を画面上で区別する。失敗時は入力とlocal原本を保持し、handoffを開始しない。
- 保存・共有操作は同じoutput gateから明示的に選択し、handoff先では自社ロゴとキャラクターで準備中を示す。Cloudflare Accessの認証境界を迂回せず、Worker APIの認証・認可が成功した場合だけbootstrap、claim、保存・共有処理を行う。認証前に本文・画像を送信せず、準備完了後に保存結果に応じた画面へ進む。
- handoffの待機表示は期限、結果不明、認証失敗を進捗として偽装しない。期限切れ・結果不明はlocal原本を保持して再試行または再確認を案内する。
- `prefers-reduced-motion: reduce` では押下の拡大や背景遷移を抑え、状態の色・文言・フォーカスでフィードバックを維持する。

## Consequences

- 編集・保存・共有の状態が同じ視覚言語で確認でき、認証画面から戻った利用者も準備中と失敗を区別できる。
- キャラクター画像は自社の採用assetだけを参照する。Workerで配信する画像assetの経路は、公開R2や管理URLを作らず、同一originの静的asset routingで実装する。
- 拡張側の画像収集が不完全な既存draftに最後の画面を推測で補完することはしない。画像がない手順は、利用者へ再記録を案内する。各操作と画像IDを保存するcapture側の契約は別担当の変更で同期する。

## Boundaries

Cloudflare Accessの設定変更、認証迂回、管理URLの公開、外部AI APIの追加、共有リンクの自動発行、画像編集機能の拡張、PDF/HTML出力は本ADRの対象外である。
